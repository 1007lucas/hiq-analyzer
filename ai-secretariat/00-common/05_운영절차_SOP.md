# 05_운영절차 SOP (비서실 운영 표준)

## 1. 일일 루틴 (사용자 소요 약 10분)

| 시각 | 단계 | 행동 | 비서 |
|------|------|------|------|
| 07:00~08:00 | 수신 | PLAN DAY, INTEL NEWS, CHIEF MORNING 보고가 순서대로 도착 | – |
| 08:00~08:10 | 확정 | CHIEF MORNING의 "결정 필요"에 답하고 오늘 P0/P1을 확정. 변경이 있으면 PLAN에 `/변경` | CHIEF→PLAN |
| 업무 중 | 요청 | 필요할 때 해당 비서에게 직접 요청. 비서가 낸 **이관 메모**는 받는 비서에게 복사 | 전 비서 |
| 18:00 | 마감 | PLAN EOD에 체크박스로 답변(✅/이월/삭제). 이월은 날짜를 함께 | PLAN |
| 21:30 | 체크인 | GROW CHECKIN에 습관 체크 답변 | GROW |

**규칙**
- 보고를 읽고 답하지 않은 "결정 필요"는 다음 날 자동으로 다시 올라온다(비서실장 지침).
- 하루 P1은 최대 3개. 4개째를 추가하려면 하나를 P2로 내린다.

## 2. 주간 루틴 (금 20분 + 월 10분)

**금요일 17:00 — 주간 보고 수집**
1. 각 비서(PLAN·INTEL·WRITE·FIN·GROW)에 `/주간` 명령 또는 자동 WEEKLY 보고 수신.
2. 5개 보고의 "■ 핵심 3줄"만 복사해 CHIEF 대화창에 붙인다(`주간 리뷰 시작` + 붙여넣기).
3. CHIEF REVIEW 보고를 받고 **지침 개선 제안**에 대해 채택/기각을 답한다.
4. 채택된 지침 수정은 바로 반영(해당 비서 GPT/프로젝트 지침 수정 → `INSTRUCTIONS.md` 변경 이력에 날짜 기록).

**월요일 08:30 — 주간 계획**
1. CHIEF PLANWK 초안을 받아 이번 주 P1 목표 3개를 확정.
2. 확정 목록을 PLAN에 `/등록` 명령으로 할일 원장에 넣는다(PLAN이 원장 추가용 행을 출력 → 원장 파일에 붙임).
3. CHIEF가 낸 비서별 이관 메모를 각 비서에 전달.

## 3. 월간 루틴 (1일, 30분) — "원장 동기화의 날"

1. FIN MONTHLY 보고 수신 → 다음 달 예산 승인, 구독 해지/유지 결정.
2. **원장 동기화**: 지난달 대화 중 "기록" 명령으로 받은 추가 행들이 원장 파일에 모두 반영되었는지 확인하고, 6개 비서의 지식 파일을 **재업로드**한다.
   - 전 비서: `02_내프로필.md`(변경 시)
   - PLAN: 할일 원장, 프로젝트 목록
   - INTEL: 관심 키워드, 리서치 큐, 아카이브 색인
   - WRITE: 연락처, 템플릿 목록
   - FIN: 장부 CSV, 구독·계약 목록
   - GROW: 습관 트래커, 학습 로드맵, 독서 목록
3. 비서실장 월간 점검(수동): CHIEF에 `/월간점검` → 결정 로그 정리, P3 항목 삭제/승격, 보고 유용도 집계(👍/👎 비율).
4. 사용 플랫폼의 **지식 파일 개수·용량** 확인(GPT 20개 제한). 아카이브는 색인 파일 1개로 압축.

## 4. 분기 루틴 (첫 월요일, 1시간)

| 항목 | 기준 | 조치 |
|------|------|------|
| 비서별 유용도 | 👍 비율 70% 미만 | 지침 재작성 또는 보고 빈도 축소 |
| 자동화 피로 | 읽지 않은 자동 보고 30% 이상 | 해당 작업 OFF 또는 주 단위로 변경 |
| 역할 중복 | 두 비서가 같은 종류 보고를 냄 | 담당 영역 재정의(공통지침 "담당 영역" 수정) |
| 공백 영역 | 이관 메모가 갈 곳이 없는 요청이 분기 3회 이상 | 7번째 비서 신설 검토 |
| 지침 길이 | 8,000자 근접 | 세부 규칙을 지식 파일로 이동 |

분기 회고 결과는 `01-chief-of-staff/knowledge/결정로그.md`의 "분기 회고" 섹션에 기록.

## 5. 지침 수정 절차 (변경 관리)

1. 문제 사례를 한 줄로 적는다(예: "EOD 보고가 12줄로 길어짐").
2. 해당 비서 `INSTRUCTIONS.md`의 관련 규칙만 수정. 공통 규칙이면 `01_공통지침모듈.md`를 먼저 수정하고 6개 파일에 반영.
3. GPT/프로젝트 지침란에 다시 붙인다.
4. 파일 하단 "변경 이력"에 날짜·내용 기록.
5. 1주 관찰 후 효과 없으면 원복.

## 6. 장애·예외 처리

| 상황 | 처리 |
|------|------|
| 자동 보고가 오지 않음 | 예약 작업 상태 확인 → 수동으로 트리거 원문을 붙여 실행 → 작업 재등록 |
| 비서가 사실을 지어냄 | 해당 보고에 👎 + "출처 없음". 지침 [사실성] 규칙 강조 문구 추가 |
| 비서가 다른 비서 영역을 침범 | 이관 메모로 되돌리고, 담당 영역 문구를 지침에 추가 |
| 지식 파일 20개 초과 | 월간 아카이브를 색인 1개로 병합 |
| 민감 정보 노출 우려 | 장부·연락처는 실명·계좌번호 대신 코드(카드A, 거래처C) 사용. 프로필에 수치 대신 구조만 기재 |
| 플랫폼 장애 | 다른 플랫폼(GPT↔Claude)의 같은 비서로 임시 전환. 지침 동일 |

## 7. 보안·개인정보 원칙

- 비서에게 올리는 파일에 계좌번호·주민번호·비밀번호를 넣지 않는다.
- 거래처·사람은 코드명 또는 이니셜로 적고, 실명 매핑표는 비서 밖(개인 메모)에 둔다.
- 발송·결제·삭제는 항상 사용자가 직접 한다. 비서는 초안·체크리스트까지.
- 세무·법률·의료 관련 보고에는 "전문가 확인 필요" 문구가 있는지 확인한다.
