# 03_보고형식 표준

모든 비서가 같은 틀로 보고해야 비서실장이 취합할 수 있고, 사용자는 어디를 읽을지 익힐 수 있습니다.

## 1. 표준 보고 블록

```
[코드] 보고유형 | YYYY-MM-DD HH:mm
■ 핵심 3줄
1. (가장 중요한 사실 또는 변화)
2.
3.
■ 결정 필요
- Q1. (질문) → 선택지 A / B (권고: A, 이유 한 줄)
- 없음
■ 상세
(표 또는 불릿. 7줄 넘으면 "▼ 더보기" 아래로 내림)
■ 다음 행동
- [ ] 내가(비서) 할 것:
- [ ] 사용자가 할 것:
→ 이관: [코드] | 요청: | 기한: | 맥락:
```

## 3. 우선순위·상태 태그

| 태그 | 의미 | 처리 기준 |
|------|------|-----------|
| P0 지금 | 오늘 안에 하지 않으면 금전·신뢰 손실 | 브리핑 최상단, 알림 |

## 4. 이관 메모 규격

```
→ 이관: [WRITE] | 요청: 김OO 대표에게 미팅 일정 변경 요청 메일 초안 | 기한: 2026-11-13 | 맥락: 원래 11/15 14:00, 11/17 오후로 변경 희망, 사유는 외부 일정 중복
```

- 받는 비서 코드는 대괄호로.
- 요청은 **동사로 끝나는 한 문장**.
- 맥락은 받는 비서가 질문 없이 처리할 수 있는 최소 정보.
- 사용자는 이 블록을 복사해 해당 비서 대화창에 붙인다. 받는 비서는 "이관 메모 접수"로 시작해 처리한다.

## 5. 원장 추가용 출력 규격 ("기록" 명령 시)

비서는 원장 파일의 형식에 맞는 행(또는 블록)만 출력한다. 예:

```
<!-- 할일원장 추가 -->
| T-0142 | HIQ 베타 안내 메일 발송 | PJ1 | P1 | 2026-11-14 | ⏳대기 | WRITE 초안 수령 후 |
```

```
<!-- 장부 추가 (CSV) -->
2026-11-12,지출,구독,Vercel Pro,20.00,USD,PJ1,카드A,월 구독
```
