# 개인 AI 비서실 (Personal AI Secretariat) — 설치·운영 가이드

> 6명의 AI 비서로 구성된 개인 비서실을 **프로젝트(Projects) + 맞춤형 GPT + 정기 자동화(예약 작업)** 방식으로 구축하기 위한 전체 설계서입니다.
> 각 폴더의 `INSTRUCTIONS.md`는 그대로 복사해 GPT/프로젝트 지침란에 붙일 수 있고, `knowledge/`의 파일은 채운 뒤 지식(Knowledge)으로 업로드합니다.

## 2. 구축 방식: 3개의 층

| 층 | 역할 | ChatGPT | Claude |
|----|------|---------|--------|
| **① 비서(에이전트)** | 역할·성격·지침 | 맞춤형 GPT (지침 + 지식 + 기능) | 프로젝트 (지침 + 지식) |
| **② 자료(기억)** | 비서가 참고하는 파일, 누적 기록 | GPT 지식(최대 20개 파일) + 프로젝트 파일 | 프로젝트 지식 + 연결된 Notion/Drive |
| **③ 자동화(리듬)** | 정해진 시각에 비서를 깨워 보고 생성 | 작업(Tasks) 예약 | 예약 작업(Scheduled tasks) / 커넥터(Gmail·Calendar·Notion) |

**원칙**
- 비서 1명 = GPT 1개(또는 프로젝트 1개). 역할을 섞지 않는다.
- 비서는 서로 직접 대화하지 못한다. 비서 간 전달은 **이관 메모**(표준 블록)를 사용자가 복사해 전달하거나, 비서실장이 **취합 모드**에서 다른 비서의 보고를 입력받아 처리한다.
- 모든 자료의 **원장(source of truth)은 파일**이다(Markdown/CSV). 비서의 대화 기억은 보조 수단이며, 월 1회 원장을 갱신해 지식에 재업로드한다.
- 자동 보고는 **"결정이 필요한 것"**을 맨 위에 올린다. 읽고 끝나는 보고는 실패한 보고다.

## 3. 설치 순서 (Day 1 ~ Day 3)

### Day 1 — 기반 (약 1시간)
1. `00-common/02_내프로필.md`를 열어 **본인 정보를 채운다** (직업, 진행 중인 프로젝트, 근무 시간, 보고 선호, 관심 키워드). 이 파일은 6개 비서 모두에 업로드된다.
2. 자료 보관 위치를 하나 정한다(권장: Notion 워크스페이스 또는 Google Drive 폴더 `AI비서실/`). 아래 폴더 구조를 그대로 만든다.
   ```
   AI비서실/
   ├── 00_공통/        프로필, 보고형식, 스케줄표
   ├── 01_비서실장/    주간보고 아카이브, 결정 로그
   ├── 02_일정업무/    할일 원장, 프로젝트 목록, 반복 일정
   ├── 03_리서치/      관심키워드, 출처 목록, 리서치 아카이브
   ├── 04_문서소통/    톤 가이드, 연락처, 템플릿, 서명
   ├── 05_재무행정/    장부(CSV), 구독·계약 목록, 세무 캘린더
   └── 06_학습성장/    학습 로드맵, 독서 목록, 습관 트래커, 회고
   ```
3. **비서실장(01)과 일정·업무 비서(02)를 먼저 만든다.** 이 둘만 있어도 비서실이 돈다.

### Day 2 — 나머지 비서 (약 1.5시간)
4. 03 리서치, 04 문서, 05 재무, 06 학습·성장 비서를 같은 방식으로 만든다.
5. 각 비서에 `knowledge/` 템플릿을 채워 업로드한다. 비어 있는 템플릿도 일단 올린다(구조를 비서가 학습한다).

### Day 3 — 자동화 (약 30분)
6. `00-common/04_자동화_스케줄표.md`의 시간표대로 예약 작업을 등록한다. 트리거 프롬프트는 표에 원문이 있다.
7. 첫 주는 **"관찰 주간"**: 보고가 오면 `👍/👎 + 한 줄 이유`로 피드백한다. 금요일 비서실장 주간 리뷰에서 지침을 1차 수정한다.

### 맞춤형 GPT 만드는 법 (비서 1명 기준, 10분)
1. ChatGPT → **GPT 탐색 → 만들기(Create)** → **구성(Configure)** 탭.
2. **이름**: `[비서실] 한결 — 비서실장` 형식. **설명**: README의 "역할 한 줄".
3. **지침**: 해당 폴더 `INSTRUCTIONS.md` 전체를 붙인다(8,000자 제한 안에 맞춰져 있음).
4. **대화 시작 문구**: README의 "명령어" 4개를 넣는다.
5. **지식**: `00-common/02_내프로필.md` + 해당 비서 `knowledge/` 파일들.
6. **기능**: 리서치 비서는 웹 검색 ON, 재무 비서는 코드 인터프리터(CSV 계산) ON, 문서 비서는 캔버스 ON.
7. **공유 범위**: 나만 보기.

### Claude 프로젝트로 만드는 법 (비서 1명 기준, 10분)
1. Claude → **프로젝트 → 새 프로젝트**. 이름은 GPT와 동일하게.
2. **프로젝트 지침**에 `INSTRUCTIONS.md`를 붙인다.
3. **프로젝트 지식**에 프로필 + `knowledge/` 파일 업로드.
4. 커넥터 연결: 02 일정 비서 ↔ Google Calendar, 04 문서 비서 ↔ Gmail, 전 비서 ↔ Notion(자료 보관소).
5. 예약 작업은 스케줄표의 트리거 프롬프트로 등록한다.

> 두 플랫폼을 함께 쓸 경우: **GPT = 대화형 비서**, **Claude 프로젝트 = 커넥터(캘린더·메일·Notion) 작업 담당**으로 나누는 것이 가장 단순합니다. 지침은 동일 파일을 쓰므로 둘 다 유지해도 관리 비용이 거의 없습니다.

## 4. 보고 체계 (누가 누구에게, 언제)

```
 07:00 PLAN  ─ 오늘 일정·할일 브리핑 ─┐
 07:30 INTEL ─ 아침 뉴스 브리핑 ──────┼─▶ 08:00 CHIEF 모닝 브리핑 (우선순위 3 + 결정 질문)
 (금)  FIN   ─ 주간 현금흐름 ─────────┘
 18:00 PLAN  ─ 마감 체크·내일 준비
 21:30 GROW  ─ 오늘의 학습·습관 체크인
 ───────────────────────────────────────────────────────────
 (금 17:00) 전 비서 주간 보고 ─▶ CHIEF 주간 리뷰 ─▶ (월 08:30) CHIEF 주간 계획
 (매월 1일) FIN 월간 재무 보고 + 구독·갱신 점검 ─▶ CHIEF 월간 점검
 (분기 첫 주) CHIEF 분기 회고 + 지침 개정
```

- 보고 헤더 공통 규격: `[코드] 보고유형 | YYYY-MM-DD HH:mm` → `■ 핵심 3줄 → ■ 결정 필요 → ■ 상세 → ■ 다음 행동` (`00-common/03_보고형식_표준.md` 참조).
- 우선순위 태그: `P0 지금` `P1 오늘` `P2 이번 주` `P3 대기`. 상태 태그: `⏳대기 ▶진행 ✅완료 ⛔보류 🔁반복`.
- 비서 간 전달은 **이관 메모** 블록으로만 한다(`→ 받는 비서 | 요청 | 기한 | 첨부 맥락`).

## 5. 운영 리듬 요약

| 주기 | 할 일 | 담당 | 소요 |
|------|-------|------|------|
| 매일 | 모닝 브리핑 읽고 `P0/P1` 확정 → 저녁 마감 체크 응답 → 학습 체크인 | 사용자 + CHIEF/PLAN/GROW | 10분 |
| 매주 금 | 각 비서 주간 보고 → 비서실장 주간 리뷰 → 지침·원장 소수정 | CHIEF | 20분 |
| 매주 월 | 주간 계획 확정, 이번 주 P1 목록 PLAN에 등록 | CHIEF→PLAN | 10분 |
| 매월 1일 | 재무 월간 보고, 구독·계약 갱신 결정, **지식 파일 재업로드(원장 동기화)** | FIN, 전 비서 | 30분 |
| 분기 | 비서별 성과 점검(유용한 보고 비율), 지침 개정, 비서 추가/폐지 | CHIEF | 1시간 |

세부 절차는 `00-common/05_운영절차_SOP.md`.

## 6. 확장

- 7번째 비서 추가 예: **사업·콘텐츠 비서(BIZ)** — HIQ 분석기 같은 서비스 운영·콘텐츠 제작·고객 응대. `02-schedule-task/`를 복제해 역할·업무·자료만 바꾸면 된다(설계서 양식 동일).
- 비서를 합치는 기준: 한 비서의 주간 보고가 2주 연속 "특이사항 없음"이면 다른 비서에 흡수.
- 비서를 나누는 기준: 한 비서의 지식 파일이 15개를 넘거나 지침이 8,000자를 넘기면 분리.
